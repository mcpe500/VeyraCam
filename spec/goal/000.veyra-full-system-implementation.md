## 1. Executive Summary & Core Invariants

Veyra transforms Android smartphones into high-performance, low-latency PC virtual webcams operating across four distinct transport mechanisms: **Wi-Fi LAN**, **Wi-Fi Direct (P2P)**, **USB (ADB & Native Bulk)**, and **Bluetooth Classic (RFCOMM)**.

### Non-Negotiable Core Invariants:
1. **Zero-Copy Native Media Path:**
   `Camera Sensor → Camera2 Surface → MediaCodec H.264 HW → Native Buffer → Veyra Packetizer → Transport → Veyra Core C++ → Jitter Buffer → Media Foundation Decoder → D3D11 NV12 Texture → Virtual Camera / UI Preview`
   *Dart/Flutter code NEVER touches raw video frames or encoded video NAL packets.*
2. **Single Canonical Camera Identity:**
   PC applications (Zoom, Discord, Teams, OBS, Google Meet) detect only **one** device: `Veyra Camera`. The transport medium is an internal implementation detail and never alters the virtual device identity.
3. **Sub-500ms Seamless Handoff:**
   Switching between USB, Wi-Fi, and Bluetooth occurs transparently with keyframe request/switchover without resetting or freezing the downstream virtual camera feed.
4. **Old Device Performance Compatibility:**
   Sustainable streaming on low-end hardware (Android 7.0+, 2 GB RAM, 4-core ARM; Windows 10, 4 GB RAM, dual-core CPU) with memory bounded below 160 MB PSS on mobile and below 50 MB idle / 150 MB active on desktop.

## 3. Detailed Subsystem Specifications & Implementation

### Module 1: Shared Native Core (`native/core`)

1. **Binary Packet Protocol (`protocol.h` & `packetizer.cpp`):**
   - Fixed ~24-byte header:
     - `magic` (`0x56455952` = "VEYR")
     - `version` (`0x01`)
     - `flags` (Keyframe `0x01`, Audio `0x02`, Encrypted `0x04`, Telemetry `0x08`)
     - `sessionId` (`uint32_t`)
     - `streamId` (`uint16_t`)
     - `frameId` (`uint32_t`)
     - `sequence` (`uint32_t`)
     - `fragmentIndex` (`uint16_t`)
     - `fragmentCount` (`uint16_t`)
     - `timestampUs` (`uint64_t`)
     - `payloadLength` (`uint16_t`)
   - MTU packetization bounded to 1200 bytes for fragmentation-free transport across Wi-Fi, USB, and RFCOMM.
2. **Lock-Free Bounded Ring Buffer (`ring_buffer.h`):**
   - Zero dynamic per-frame allocation (`malloc`/`free` prohibited in hot path).
   - Pre-allocated packet and frame descriptors reused via circular indices.
   - Bounded queues with strict `drop-stale` backpressure policy (never stall when buffer is saturated; drop stale non-keyframes to maintain realtime stream).
3. **Adaptive Jitter Buffer (`jitter_buffer.h`):**
   - 20 ms buffer on stable LAN / USB; adaptive 40–80 ms on fluctuating Wi-Fi.
   - Gap detection: If keyframe fragment is missing, immediately fire `0x08 REQUEST_IDR` back to mobile sender.
4. **Session Security & Cryptography (`crypto.h`):**
   - X25519 Elliptic-Curve Diffie-Hellman (ECDH) key exchange during pairing.
   - ChaCha20-Poly1305 AEAD symmetric payload encryption per packet with monotonic sequence nonce.

### Module 2: Android Native Engine (`native/android` & `apps/veyracam`)

1. **Camera2 API Controller (`Camera2Controller.kt`):**
   - Direct Camera2 hardware session without Flutter camera plugin.
   - Dual Surface Pipeline:
     - Output Surface A: MediaCodec Input Surface (`createInputSurface()`).
     - Output Surface B: Optional local preview TextureView surface (throttled to 360p15 to conserve GPU/thermal budget on low-end hardware).
   - Manual 3A controls: Exposure compensation, zoom factor, manual focus distance, flash/torch toggle, white balance lock, and sensor orientation matrix.
2. **MediaCodec Hardware H.264 Encoder (`H264Encoder.kt`):**
   - Surface input mode for zero YUV-to-RGB or byte-buffer copies.
   - Low latency parameters: `KEY_LATENCY = 0`, `KEY_BITRATE_MODE = BITRATE_MODE_CBR`, `KEY_I_FRAME_INTERVAL = 1`.
   - Baseline / Main profile (H.264 / AVC).
   - Dynamic quality ladder: 240p, 360p, 480p, 720p, 1080p @ 15, 24, 30, 60 FPS (bitrate 150 kbps to 10 Mbps).
3. **VeyraStreamingService (`VeyraStreamingService.kt`):**
   - Android 14+ compatible `camera | microphone` foreground service with persistent status notification.
   - Partial WakeLock keeping CPU and network alive.
   - **Screen-Off Mode:** Automatically tears down preview surface when screen is turned off while keeping MediaCodec and transport pipeline active (saving ~40% display/GPU power).
4. **Battery & Thermal Controller (`ThermalController.kt`):**
   - Continuous thermal status listener:
     - Temperature <40°C: Maximum selected profile (e.g. 1080p30).
     - Temperature 40–44°C: Step down to 720p30.
     - Temperature 45–48°C: Step down to 720p24 / 480p24.
     - Temperature >48°C: Emergency low-power mode (360p15, 300 kbps).
   - Automatic bitrate throttling on packet loss signals.

---

### Module 3: Windows Native Engine & Virtual Camera (`native/windows`)

1. **Windows Network Engine (`iocp_udp_server.cpp`):**
   - High-throughput asynchronous I/O Completion Ports (IOCP) for WinSock UDP video and TCP control channels.
   - Native Windows RFCOMM Bluetooth socket communication.
2. **Media Foundation Hardware Decoder (`mf_decoder.cpp`):**
   - Media Foundation H.264 Decoder (`CLSID_CMSH264DecoderMFT`) with DXVA2 / Direct3D 11 hardware acceleration.
   - Outputs NV12 Direct3D 11 textures.
   - **Single-Decode Architecture:** One decoded NV12 frame is shared simultaneously to the virtual camera pipeline and the Flutter preview texture bridge via D3D11 shared handles (zero double-decode).
3. **Windows 11 Virtual Camera Backend (`IMFVirtualCamera`):**
   - Built on `MFCreateVirtualCamera` with `MFVirtualCameraType_SoftwareCameraSource`.
   - Registers canonical device identity: `Veyra Camera`.
   - Direct NV12 stream delivery to Windows Camera subsystem.
4. **Windows 10 DirectShow COM Source Filter Fallback (`dshow_filter.cpp`):**
   - CSourceStream DirectShow filter delivering RGB/NV12 video to legacy capture APIs on Windows 10 Build 1809+.
5. **VeyraCore Background Service (`VeyraCore.exe`):**
   - Lightweight standalone executable with System Tray icon.
   - Working set memory <50 MB during idle, <150 MB during active 720p streaming.
   - Survives Flutter UI window closure so live Zoom/Teams calls are never interrupted.

---

### Module 4: Multi-Transport Subsystem & Seamless Handoff

1. **Wi-Fi LAN Transport:**
   - Video channel: High-speed UDP with packet reassembly.
   - Control channel: TCP with JSON handshake and binary control commands.
   - Discovery: mDNS broadcast + UDP beacon fallback.
2. **Wi-Fi Direct (P2P) Transport:**
   - Android `WifiP2pManager` peer-to-peer connection for wireless streaming without a local Wi-Fi router.
3. **USB Transport:**
   - **V1 Mode:** Automatic ADB port forwarding (`adb forward tcp:5150 tcp:5150`).
   - **V2 Mode:** Android Open Accessory (AOA) / WinUSB bulk endpoint driver.
4. **Bluetooth Classic Transport (RFCOMM):**
   - RFCOMM SPP socket channel.
   - Adaptive Low-Bandwidth Mode: Dynamically caps stream at 240p/360p @ 15 fps (200–500 kbps) with aggressive packet drop to eliminate lag.
5. **Auto Transport Manager & Handoff Engine (`transport_manager.cpp`):**
   - Live link scoring (RTT, jitter, packet loss rate).
   - Sub-500ms Handoff Sequence:
     1. Open alternate candidate transport.
     2. Send `0x08 REQUEST_IDR` to sender on new transport.
     3. Await first valid IDR keyframe packet.
     4. Switch decoder input source seamlessly.
     5. Close old transport without resetting `Veyra Camera` device.

### Module 5: Protocol, Security & Remote Controls

1. **Binary Command Hot Path:**
   - `0x01 HELLO` / `0x02 CAPABILITIES`
   - `0x03 START_STREAM` / `0x04 STOP_STREAM`
   - `0x05 SET_ZOOM` / `0x06 SET_EXPOSURE` / `0x07 SET_FOCUS`
   - `0x08 REQUEST_IDR` / `0x09 SET_BITRATE`
   - `0x0A TRANSPORT_SWITCH` / `0x0B PING` / `0x0C PONG` / `0x0D STATS`
2. **Pairing Flow & Security:**
   - 6-digit one-time PIN or QR verification on initial connection.
   - Public key exchange and trusted device store.
3. **High-Precision Telemetry HUD:**
   - Per-stage latency timestamps: Capture (ms) → Encode (ms) → Network (ms) → Jitter (ms) → Decode (ms) → Presentation (ms).
   - Telemetry throttled to 2–5 Hz for lightweight UI updates.
